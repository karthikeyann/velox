Key Observations:
1. Velox is the GPU engine for both Presto and Gluten. Both platforms delegate GPU execution to Velox's experimental/cudf module. GPU operator coverage is identical at the engine level.
2. Gluten adds GPU shuffle. Gluten has GPU shuffle writer/reader not present in Presto Native, giving it a distinct advantage for Spark workloads.
3. Complex types are a shared gap. ARRAY/MAP/STRUCT support is incomplete on GPU across all platforms, and Gluten marks them Not Supported even on CPU.
4. Memory is the production blocker. No platform has unified CPU+GPU memory management. GPU OOM causes crashes, not graceful spill.
5. Expression coverage gates real GPU usage. A single unsupported function in FilterProject forces the entire operator to CPU.
